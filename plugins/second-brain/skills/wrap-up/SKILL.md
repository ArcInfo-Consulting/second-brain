# Wrap up

Save what future sessions will need. A new session doesn't remember this conversation, and a short session never reaches compaction, so this is how its results last.

1. Work out which project this session belongs to. If it covers more than one, handle each one. If none is clear, ask.
2. Find the project's folder on its `Local` line in `INDEX.md`. If it has no `Local` line, use a folder named after the project in the work folder, and add the line. Read `STATUS.md` there. If it doesn't exist, create it from the sections below.
3. Pull out only what came from this session:
   - **Decisions:** what was decided, by whom, and why, if known
   - **Commitments:** who owes what, and by when
   - **Open questions:** what's unresolved, and who can answer
   - **Next steps:** the next useful actions
   - **Current state:** a two- or three-line summary to replace the old one
4. Show the proposed changes and ask for corrections. Skip this step only if the user asked you to save without review.
5. Update the file:
   - Set `Last updated` to today's date.
   - Replace `Current state`.
   - Add new items with a date, such as `- 2026-11-01: Chose vendor B (Priya)`.
   - Mark finished commitments and answered questions as done instead of deleting them, so the history stays useful.
6. If this session found a new project location, offer to add it to `INDEX.md`.

Record facts from the session, not guesses. If an owner or date is unknown, write `unknown`.

Keep `STATUS.md` short enough to scan. If it passes about 200 lines, offer to move older finished items to `STATUS-archive.md` in the same folder.
